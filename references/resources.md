# GO-BUILD: Design & Development Resources

## Назначение ресурсов

GO-BUILD может использовать проверенные внешние ресурсы для:
* поиска UI-компонентов;
* поиска подходящих библиотек;
* анализа современных паттернов;
* поиска готовых решений;
* изучения структуры интерфейсов;
* выбора подходящих иконок;
* проверки существующих инструментов перед созданием собственного решения.

**Использование ресурсов не означает автоматическое копирование дизайна или структуры.**

Каждое найденное решение обязано пройти проверку:

**Подходит ли оно конкретному продукту и решает ли реальную задачу?**

## 1. Обязательные UI и Component Resources

* [shadcn/ui Components](https://ui.shadcn.com/docs/components) — эталонная библиотека доступных, кастомизируемых React-компонентов.
* [shadcn/ui Icon Libraries](https://www.shadcn.io/icons/libraries) — каталог проверенных наборов интерфейсных иконок.
* [Lucide React Icons](https://lucide.dev/guide/react/) — основной приоритет векторных SVG-иконок для веб-приложений.
* [Hugeicons](https://hugeicons.com/) — премиальная библиотека строгих интерфейсных иконок.

---

## 2. Поиск библиотек и аудит зависимостей

* [Libraries.dev](https://libraries.dev/) — поиск open-source библиотек, пакетов и модулей.

Использовать для:
* поиска библиотек;
* проверки популярности и частоты релизов;
* оценки активности и поддержки проекта;
* поиска альтернатив;
* изучения зависимостей и лицензий.

### Чек-лист перед добавлением любой новой библиотеки:
Перед установкой зависимости агент обязан проверить:
1. **Действительно ли она нужна?** *(Нельзя ли решить задачу стандартными средствами языка/фреймворка)*.
2. **Активно ли она поддерживается?** *(Последние коммиты, закрытие issues)*.
3. **Нет ли уже подходящего решения в текущем проекте?**
4. **Не создаёт ли она лишнюю транзитивную зависимость?**
5. **Оправдан ли её вес (bundle size) и сложность интеграции?**

## 4. Правила использования Design Resources

### Запрещается:
* слепо копировать найденный дизайн;
* переносить чужую структуру страницы без анализа;
* копировать декоративные элементы;
* использовать найденные решения только потому, что они выглядят «современно» или «трендово»;
* превращать проект в хаотичную смесь нескольких разнородных референсов;
* нарушать Anti-AI-Slop ради повторения чужого дизайна.

### Разрешается использовать ресурсы для ответа на вопросы:
* Как лучше решить конкретную UI-задачу пользователя?
* Существует ли уже готовый проверенный паттерн для этого функционала?
* Какую информационную структуру используют для подобного типа данных?
* Какие библиотеки подходят под текущий технологический стек?
* Какие варианты layout эффективнее для конкретного пользовательского сценария?

## 5. Протокол: Reference → Analysis → Adaptation

GO-BUILD категорически запрещено работать по принципу:
```text
[ЗАПРЕЩЕНО]:
Нашёл дизайн → Скопировал → Адаптировал текст
```

### Обязательный процесс разработки с референсом:
```text
1. Задача проекта (первоначальный смысл и сценарий)
       ↓
2. Поиск подходящих решений и паттернов
       ↓
3. Анализ найденных подходов
       ↓
4. Определение полезных принципов и структуры
       ↓
5. Проверка на соответствие требованиям конкретного проекта
       ↓
6. Адаптация под логику продукта
       ↓
7. Проверка Anti-AI-Slop & Design Justification
       ↓
8. Реализация
```

## 6. Приоритет собственной логики продукта

Внешний референс никогда не должен быть важнее требований и логики проекта.

Если найденное решение:
* не соответствует пользовательскому сценарию;
* усложняет интерфейс;
* добавляет лишние контейнеры или обводки;
* нарушает структуру;
* не проходит Visual Purpose Gate;
* не проходит Anti-AI-Slop;

**оно должно быть немедленно отклонено.**

---

## 7. Обязательная проверка перед использованием референса

Перед переносом любого подхода в проект необходимо ответить на 5 вопросов:

1. **Какую конкретную задачу решает этот подход?**
2. **Есть ли эта задача в нашем проекте?**
3. **Подходит ли решение нашей структуре?**
4. **Можно ли решить задачу проще?**
5. **Не нарушает ли решение правила GO-BUILD (Anti-AI-Slop, Zero-Emoji, Border Last)?**

*Если хотя бы один ответ отрицательный — решение переносить запрещено.*

---

## Главный принцип

* **Ресурсы используются для поиска решений, а не для поиска того, что можно скопировать.**
* **Референс — это источник анализа, а не готовый шаблон проекта.**
* **Структура и логика продукта всегда важнее визуального вдохновения.**
