# GO-BUILD: User Design DNA & Visual Memory Library

Документ долговременной памяти предпочтений пользователя.
Служит накопительной базой одобренных дизайн-паттернов, цветовых палитр, типографики и ограничений (Avoid-списка).

Формула развития:
**Design → Feedback → Extract Pattern → Remember → Apply → Improve**

---

## 1. Регламент обработки обратной связи

### 1.1. Положительная обратная связь (Positive Design Feedback)
Триггеры похвалы пользователя:
* «красавчик»
* «круто получилось»
* «вот это хорошо»
* «идеально»
* «оставляем»
* «вот так нравится»
* «топ»
* «запомни»
* «это оно»
* «сделай как здесь»
* «вот этот вариант лучший»

**Обязательное действие агента**:
Декомпозировать похвалу на конкретные составляющие (цвета, формы, отступы, типографика, композиция), зафиксировать их в соответствующих разделах этого документа и дать краткий ответ:
> «Зафиксировал. Этот паттерн считаем удачным и используем как референс дальше.»

*(Если похвала дана без конкретного объекта, считать её общей положительной оценкой последнего значимого решения без создания избыточно узких правил).*

### 1.2. Отрицательная обратная связь (Negative Design Memory)
Любое отвергнутое решение немедленно фиксируется в разделе **Avoid Rules** как строгий запрет на повторение аналогичной ошибки.

## 2. Success Pattern Extraction (10 аспектов декомпозиции)

После каждого особенно удачного решения интерфейс мысленно раскладывается на 10 параметров:
1. **Цветовая система**: гармония, акцент, фон, прозрачность.
2. **Типографика**: шрифты, масштаб, line-height, контраст заголовков и текста.
3. **Композиция**: сетка, баланс масс, первое впечатление.
4. **Spacing**: шкала отступов, воздух, rhythm.
5. **Контраст**: читаемость, акцентирование главного CTA.
6. **Иерархия**: визуальный порядок считывания информации.
7. **Компоненты**: конкретная реализация карточек, кнопок, форм.
8. **Декоративные элементы**: допустимый уровень графических деталей (строго функциональных).
9. **UX**: простота сценария (Правило трёх действий).
10. **Общее настроение**: сдержанность, плотность, технологичность.

## 3. Накопительная библиотека предпочтений (Visual Library)

### 3.1. Style (Стилистические направления)
*Одобренные стили (минимализм, brutalism, editorial, modern SaaS, dark UI, bento и др.):*
- [Одобрено]: Строгий минимализм с акцентом на типографику и пространство.
- [Одобрено]: Taste Design Framework (отсутствие AI-slop, отказ от шаблонных неоновых градиентов).
- [Одобрено]: Warm Parchment Minimal (серовато-бумажная эстетика mole.fit: натуральная бумага, литературная книжная антиква, моноширинная нумерация инструментов).

### 3.2. Colors & Combinations (Цветовая память)
*Удачные цветовые сочетания и палитры:*
- Основной фон: нейтральные тёмные и светлые оттенки без едких неоновых свечений.
- [Одобрено]: Серовато-пергаментная палитра mole.fit:
  - Холст страницы: `#f5f4ed` (тёплый пергамент / плотная бумага);
  - Карточки и мокапы: `#faf9f5` (слоновая кость / ivory);
  - Плашки и технические разделители: `#e8e6dc` (тёплый песок);
  - Чернильный акцент текста и главных CTA: `#1B365D` (глубокий индиго);
  - Тонкие границы (Border Last): `#d8d5c8` и `#edebe1`.
- Текст: высокий контраст основного текста и приглушённый secondary text для иерархии.

### 3.3. Typography (Шрифтовая культура)
*Предпочитаемые шрифты, размеры и интервалы:*
- Шрифты: современные гротески (Inter, Geist, Satoshi, Roboto, SF Pro) либо классическая литературная антиква книжного набора (Charter, Georgia, Source Serif 4).
- Метки и нумерация инструментов: моноширинный шрифт (JetBrains Mono, SF Mono) в формате `00 · See it`, `01 · Features`.
- Заголовки: без капса ради капса, сбалансированные по массе.
- Текст: читаемый line-height (1.5-1.6), системный letter-spacing.

### 3.4. Components (Одобренные реализации)
*Проверенные компоненты:*
- **Buttons**: функциональные, с четким фокусом и `:active` откликом, без эмодзи.
- **Cards**: плоские поверхности без сплошных обводок (Border Last), отступы через gap, группировка связанной информации.
- **Accordion (Exclusive Animated)**: плавное схлопывание предыдущего вопроса при открытии нового на базе аппаратного CSS Grid (`grid-template-rows: 0fr ⇄ 1fr`) + `opacity` + `cubic-bezier(0.25, 1, 0.5, 1)`. Никаких рывков и мгновенных скрытий DOM.
- **Page Header**: строго название + краткое пояснение (при необходимости) + действие. Без бейджей над H1 и псевдологотипов в квадратах.
- **Navigation & Sidebar**: чистые списки разделов со строгими SVG-иконками (Lucide/Hugeicons).

### 3.5. Layout & Spacing (Сетки и ритм)
*Сетки и геометрия:*
- Ширина: constrained (`max-w-5xl`, `max-w-7xl`) для страниц/форм, reading width (`max-w-2xl`) для текста.
- Spacing: системная шкала (4, 8, 12, 16, 24, 32, 48, 64 px).
- Сетки: Flex для одномерных рядов, Grid для двухмерных дашбордов.
- Оконная адаптивность (Window Adaptivity):
  - Принцип Window-First: доступное пространство определяет layout.
  - Приоритет контента: PRIMARY (всегда на экране), SECONDARY (схлопывание/перенос), OPTIONAL (скрытие в overflow-меню).
  - Минимальные размеры окна: явное задание Minimum Window Size во избежание деградации UX.
  - Изоляция скролла: в desktop-приложениях окно не скроллится целиком; скролл разрешен только внутри изолированных списков/таблиц/холстов.

### 3.6. Visual Patterns
- Формы: сбалансированные скругления (`rounded-lg`, `rounded-xl`), без экстремальных радиусов.
- Свободное пространство: активное использование whitespace как разделителя.

## 4. Negative Design Memory (Avoid Rules)

Категорически запрещённые паттерны, отвергнутые пользователем или стандартом:
* **Avoid: Emojis** — полный запрет эмодзи во всех элементах интерфейса.
* **Avoid: AI-Slop & Neon** — запрет едких неоновых подсветок, градиентных рамок, мерцающего пластика.
* **Avoid: Pre-Header Badges** — запрещены надзаголовочные плашки (`[ DASHBOARD ]`, `[ PLATFORM ]`).
* **Avoid: Fake Logo Boxes** — запрещены квадратные контейнеры с одной буквой или иконкой перед H1 (`[ A ]`).
* **Avoid: Dot Labels** — категорически запрещены любые точки перед текстом ради индикации статуса (`● ONLINE`, `● SECURITY`, `● Live`). Никаких цветных кружков перед системными надписями.
* **Avoid: Subtitle Redundancy** — запрещено выводить служебные подзаголовки рядом с логотипом/названием (например, `macOS Utility` рядом с `Vesper`). Название продукта должно стоять чисто, без избыточных пояснений.
* **Avoid: Inconsistent Cyrillic Fonts (Newsreader fallback)** — запрещено использовать шрифты с частичной или деградирующей поддержкой кириллицы. Для литературной книжной антиквы обязателен `Source Serif 4` (с кириллическим диапазоном Google Fonts) в паре с системными `Charter` и `Georgia`, чтобы русские заголовки выглядели идентично английским по оптической массе и рисунку засечек.
* **Avoid: Notarization & Telemetry Badges** — запрещены искусственные плашки вида `Apple Notarized`, `Zero Telemetry`, `Notarization`, `Encrypted` в trust-барах и футере. Если софт приватный или нативный, это формулируется естественным языком в тексте продукта («Runs entirely on your Mac; files are never uploaded»), а не выносится как декоративный бейдж.
* **Avoid: Non-exclusive Multi-open Accordion** — запрещены аккордеоны FAQ, где открытые пункты остаются висеть при клике на следующий. При открытии любого вопроса предыдущий обязан автоматически и плавно закрываться.
* **Avoid: Card-Hell & Overbordering** — запрещена обводка каждого блока и бесконечная вложенность карточек.
* **Avoid: Line & Divider Clutter** — категорически запрещено перегружать интерфейс полосами, границами каждого элемента и разделительными линиями (divide-y, border-b, рамки у каждого блока). Структурирование и иерархия должны строиться на воздухе, отступах (gap, padding), мягких фоновых поверхностях и типографике, сохраняя спокойный книжный стиль, а не вид табличной сетки.
* **Avoid: Fake Metrics & Statuses** — запрещены выдуманные цифры (`99.9%`, `10K+`) и симуляции статусов.
* **Avoid: Fake Product Context** — категорически запрещено самостоятельно добавлять в интерфейс версии (`PRODUCT // V1.0`), билд-информацию (`BUILD 2026.09`), релизы, названия внутренних систем (`SYSTEM V2.4`), псевдотехнические названия, режимы работы, сканеры, названия движков и фейковые идентификаторы.
* **Avoid: Version Information as Header Decoration** — запрещено автоматически лепить `// V1.0` или `VERSION 1.0` рядом с названием продукта. Версия не является украшением хедера и разрешена только в About, DevTools, поддержке или по прямой просьбе пользователя.
* **Avoid: Fake Technical Aesthetic & Statuses without Consequences** — запрещено нагнетать псевдотехнологичность через случайные системные ярлыки (`IDLE SCAN`, `CORE ACTIVE`, `SYSTEM ONLINE`, `PROCESSING`). Любой статус обязан иметь последствия для пользователя: если при смене статуса пользователь ничего не должен делать и интерфейс не меняется — такой статус не существует.
* **Avoid: Green Dots as Pure Decoration** — зелёная точка категорически запрещена как визуальный аксессуар (`● ONLINE`, `● ACTIVE`, `● READY`, `● IDLE`). Индикатор разрешён только при одновременном соблюдении 4 критериев: реальный, динамический, значимый, необходимый.
* **Avoid: Invented UI Storytelling (AI Atmosphere > User Request)** — строгий запрет на выдумывание дополнительного сценария, лора и «атмосферы системы» вокруг утилитарной задачи (например, выдумывание кибер-глаза с `IDLE SCAN`, `FIT 90%`, `INVERT`, `GAZE X`, `PUPIL DILATION`, `FPS 121` при запросе простого ASCII-просмотра). Продукт делает только то, о чём просил пользователь: User Request > AI Atmosphere.
* **Avoid: Unearned Information (The "Why Would User Care?" Failure)** — запрещено выводить любой текст, который не проходит тест «Почему пользователю вообще должно быть не всё равно на эту информацию?» и чек-лист из 5 вопросов (если при удалении текста ничего не меняется — текст удаляется).
* **Avoid: Hardcoded Window Coordinates & Single-Size Layouts** — запрещены жесткие координаты X/Y ($X: 300, Y: 500$) и верстка GUI/Web под один фиксированный размер окна.
* **Avoid: Blind Web-to-Desktop Embedding** — запрещен перенос веб-страницы в окно программы без адаптации (окно не должно скроллиться целиком, меню и сайдбар обязаны быть десктопными).
* **Avoid: Broken Window Resize & Inaccessible Controls** — запрещено сжатие окна до перекрытия кнопок, обрезки текста, наложения контейнеров и появления паразитного горизонтального скролла окна.
* **Avoid: Top-Left Status Dots & Corner Indicators (❌ Зелёная точка/индикатор слева сверху)** — пожизненный категорический запрет на размещение цветных точек, светодиодов и кружков (`●`, `○`, `•`) в левом верхнем углу, перед названием продукта или в шапке. Статус выносится исключительно в функциональное тело интерфейса.
* **Avoid: Header Protocol & Plan Badges (❌ Лишние бейджи вроде Pro, WireGuard в шапке)** — пожизненный запрет на размещение в Header бейджей тарифных планов (`Pro`, `Premium`, `Free`), статусов подписки, чипов протоколов (`WireGuard`, `OpenVPN`) и любых декоративных пилюль/чипов.
* **Avoid: Overloaded Top Block (❌ Перегруженный верхний блок)** — категорический запрет на загромождение верхнего блока. Шапка содержит исключительно чистое название продукта либо остаётся пустой (в утилитах).
* **Avoid: Decorative Elements Without Function (❌ Любые декоративные элементы, которые не несут функции)** — категорический запрет добавлять элементы просто «для красоты» или для заполнения пустоты. Разрешены **только функциональные** элементы, несущие прямое действие или критическую информацию.
* **Avoid: AI-Invented Filler & Hallucinated Content (Запрет додумывания от себя)** — категорический строжайший запрет самостоятельно додумывать и вставлять в интерфейс любые бейджи, плашки фичей/преимуществ (напр. 'WireGuard 2.4 Gbps', 'Zero Logs'), подсказки, демо-ключи ('Use demo key...'), подписи версий/движков ('Mona VPN Engine'), или любые другие текстовые/графические элементы ради «заполнения пустого места», о которых пользователь прямо не просил. Пустое пространство в минимализме — это чистый воздух, а не повод генерировать искусственные заполнители. Делать СТРОГО то, что запросил пользователь, без малейшей самодеятельности.
* **Avoid: Reassurance Slop & Pseudo-Trust Fillers (Запрет фальшивых заверений)** — пожизненный запрет на любые псевдоуспокаивающие фразы и бейджи: «Перевод без скрытых комиссий», «Прямой курс», «Без скрытых условий», «Безопасная сделка», «Гарантия подлинности». Интерфейс должен содержать исключительно чистые данные и действия (Количество, Валюта, Итог к оплате, Кнопка). Никакого маркетингового мусора.
* **Avoid: Cringe Buzzwords & Pseudo-Hacker Slop** — категорически запрещены инфантильные псевдохакерские термины и ярлыки в стиле сомнительного софта: `Bypass Ready`, `Fast Injection`, `Kernel Inject`, `Stealth Inject`, `Memory Bypass`, `Hook Ready`, `Payload Active`, `Anti-Detection Ready`. Статусы и шаги должны именоваться строго профессиональным инженерным языком («Готов к работе», «Подключение», «Загрузка модуля»).
* **Avoid: Cheesy 2-Option Presets** — категорически запрещены мерзкие шаблонные пары опций в стиле чит-меню (`Ghost & Blatant`, `Legit vs Rage`, `Stealth vs Aggressive`, `Silent vs Loud`). Запрещено искусственно навязывать пользователю бинарный выбор («2 options») с пафосными эпитетами ради видимости функционала. Опции обязаны отражать реальные технические параметры (`TCP / UDP`, `Стандартный / Расширенный`).
* **Avoid: Hyperbolic Performance & Umbrella Clichés** — запрещены пустые хвалебные слова в названиях опций, переключателей и бейджей (`Top Performance`, `Ultra Performance`, `Maximum Speed`, `Turbo Boost`, `Hyper Speed`, `Extreme Power`, `Fast Mode`), а также зонтичные маркетинговые штампы (`All-in-One`, `Ultimate Suite`, `Complete Solution`, `Full Pack`). Опции оптимизации формулируются строго через технический эффект (`Энергосбережение`, `Аппаратное ускорение`).
* **Avoid: Scope Creep & Unauthorized Expansion (Строгое соответствие запросу)** — категорический запрет самостоятельно добавлять функции, элементы UI, тексты, настройки, проверки, состояния, страницы, API, зависимости или абстракции, которых не было в запросе. Запрещено добавлять элементы «для удобства», «для красоты», «на будущее» или «по стандарту». Не менять текст, файлы и архитектуру за пределами запрошенного. Изменения строго минимальны.
* **Avoid: Redundant Code & Duplicate Creation (Сначала искать, потом создавать)** — категорически запрещено создавать новые функции, типы, компоненты или модули, если в проекте уже есть аналогичное решение, которое можно переиспользовать или адаптировать. Запрещено дублировать код из-за косметических отличий или создавать обходные пути вместо исправления существующей реализации.
* **Purity Formula (Принцип максимальной чистоты)**: интерфейс должен быть максимально чистым. Эталонная формула: **VPN + основная кнопка + статус + скорость + сервер** (Имя Продукта + Основная Кнопка + Статус + Ключевая Метрика + Селектор).

## 5. User Design DNA (Сводный профиль)

1. **Степень минимализма**: Высокая. Главный ориентир — *«Что можно убрать, чтобы стало понятнее и лучше?»*.
2. **Отношение к декору**: Нулевая толерантность к нефункциональным украшениям.
3. **Плотность информации**: Сбалансированная, с сохранением достаточного свободного пространства.
4. **Типографика**: Спокойная, уверенная, чистая, гротескная.
5. **Сценарии**: Минимально короткие по Правилу трёх действий (Зашел → Выбрал → Получил результат).

## 6. Принцип анти-зацикливания (Не клонировать вслепую)

Запоминание успешных решений **не означает**, что каждый новый проект должен быть визуальной копией предыдущего.
Накопленные предпочтения используются как:
**базовое направление → не как жесткий шаблон.**

Всегда адаптировать принципы под:
* конкретный продукт;
* целевую аудиторию;
* задачу и сценарий;
* специфику платформы.
