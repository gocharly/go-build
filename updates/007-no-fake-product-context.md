# GO-BUILD Update 007: No Fake Product Context & User Request > AI Atmosphere

## Version
v1.7.0

## Date
2026-09-07

## Type
Design Guardrails / Interface Hygiene / Anti-AI-Slop Standard

## Priority
CRITICAL

## What changed
1. **NO FAKE PRODUCT CONTEXT**: Введён категорический запрет на самостоятельное выдумывание и внедрение в интерфейс:
   * версий (`PRODUCT // V1.0`);
   * билд-информации (`BUILD 2026.09`);
   * номеров релизов и патчей;
   * названий внутренних систем (`SYSTEM V2.4`);
   * выдуманных системных имен (fake system names);
   * технических статусов (`SESSION LIVE`, `ENGINE ACTIVE`);
   * режимов работы (`IDLE SCAN`);
   * ярлыков сканеров и процессов;
   * debug-информации;
   * названий движков (`NEURAL ENGINE`);
   * бессмысленных идентификаторов.
2. **VERSION INFORMATION IS NOT DECORATION**:
   * Запрещено автоматически писать `// V1.0` или `VERSION 1.0` рядом с названием продукта.
   * Версия допустима исключительно если: (1) она важна пользователю, (2) это инструмент разработчика, (3) пользователь в разделе About, (4) версия нужна для поддержки, (5) пользователь напрямую попросил её показать.
   * Версия продукта не является декоративным элементом Header.
3. **NO FAKE TECHNICAL AESTHETIC**:
   * Запрещено создавать ощущение «технологичности» через случайный технический текст (`IDLE SCAN`, `SYSTEM READY`, `PROCESSING`, `CORE ACTIVE`, `NETWORK SECURE`). Технический текст не является дизайном.
4. **STATUS MUST HAVE CONSEQUENCES**:
   * Любой статус обязан отвечать на вопрос: *«Что изменится для пользователя, если этот статус изменится?»*. Если ничего не изменится, действий не требуется и интерфейс не меняется — статус не должен существовать.
5. **GREEN DOT ≠ GOOD DESIGN**:
   * Зелёная (и любая цветная) точка запрещена как декоративный элемент (`● ONLINE`, `● ACTIVE`, `● READY`, `● IDLE`).
   * Индикатор разрешён исключительно при соблюдении 4 строгих условий: статус реален, динамически меняется, изменение имеет значение, пользователь должен видеть этот статус.
6. **PRODUCT NAME ONLY**:
   * В Header по умолчанию находится только реальное название продукта.
   * Вопрос фильтрации: *«Нужна ли эта информация пользователю прямо сейчас?»*. Если нет — удалить.
7. **NO FAKE BUILD IDENTITY**:
   * Запрещено придумывать продукту: версию, build, codename, engine, system mode, protocol, scanner, AI mode, internal state (`APP NAME // V1.0`, `PROJECT_X / BUILD_01`, `NEURAL ENGINE`, `SYSTEM INTERFACE`, `AI POWERED TERMINAL`).
8. **INFORMATION MUST EARN ITS PLACE**:
   * Каждый текст обязан заслужить своё место в интерфейсе через чек-лист из 5 вопросов:
     1. Откуда появилась эта информация?
     2. Реальна ли она?
     3. Нужна ли она пользователю?
     4. Что пользователь сделает благодаря этой информации?
     5. Что произойдёт, если её удалить? *(Если «Ничего» — текст удаляется).*
9. **NO INVENTED UI STORYTELLING**:
   * Запрещено придумывать продукту дополнительный сценарий или «историю системы» ради атмосферы (например, превращать простой просмотрщик в псевдосканер с `IDLE SCAN`, `FIT 90%`, `INVERT`, `GAZE X`, `PUPIL DILATION`, `FPS 121`). Продукт делает только то, о чём просил пользователь.
10. **THE "WHY WOULD USER CARE?" TEST**:
    * Перед добавлением любой технической информации агент обязан задать вопрос: *«Почему пользователю вообще должно быть не всё равно на эту информацию?»*. Если конкретного ответа нет — информация не показывается.
11. **USER REQUEST > AI ATMOSPHERE (Фундаментальный принцип)**:
    * GO-BUILD никогда не добавляет атмосферу, fake-tech эстетику, терминальный стиль, системные подписи, версии, статусы, технический жаргон, если пользователь этого не просил и это не требуется функционально.
    * **Не придумывай продукту личность, систему или процессы, которых в задаче не существует.**
12. **Anti-AI-Slop Final Check расширен до 20 пунктов**:
    * Добавлены пункты проверки чистоты контекста, отсутствия декоративных версий в Header, индикаторов без последствий и выдуманного лора.

## Why
Генеративные AI-модели имеют склонность «додумывать» продукту вымышленную атмосферу (fake-tech lore): придумывать киберпанк-названия, лепить версии `// V1.0` в хедер, рисовать зелёные точки с надписями `IDLE SCAN`, `ENGINE ACTIVE`, `LIVE SESSION` и загромождать экран выдуманными метриками.
Это типичный AI-slop: агент придумывает интерфейсу историю и фейковый контекст, которого пользователь не просил. Это перегружает когнитивное восприятие, создаёт визуальный мусор и отвлекает от реальной функциональной задачи.

## New rules
* **User Request > AI Atmosphere**: Продукт делает только то, что необходимо для его функциональной цели. Никакого выдуманного контекста, процессов и личностей.
* **Product Name Only**: В заголовке только название продукта без `// V1.0` и фальшивых индикаторов.
* **Status Must Have Consequences**: Статус существует только тогда, когда его изменение требует действий от пользователя или влияет на работу интерфейса.
* **Green Dot $\neq$ Good Design**: Индикаторы разрешены только по 4 критериям (реальность, динамичность, последствия, необходимость).
* **Information Must Earn Its Place**: Любой текст, удаление которого ни на что не влияет, удаляется немедленно.
