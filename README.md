# GO-BUILD

**Архитектурный стандарт разработки цифровых продуктов и регламент дисциплины AI-ассистентов**

Версия стандарта: **v1.19.0**

---

## 1. О стандарте

**GO-BUILD** — это инженерный стандарт и регламент для автономных AI-ассистентов (Google Antigravity, Claude Code, Cursor, Roo, Windsurf), ориентированный на комплексную разработку цифровых продуктов от первоначальной идеи до протестированного, чистого решения.

Стандарт устраняет фундаментальные проблемы генеративного кода («AI-slop», декоративные заглушки, самовольное расширение скоупа, дублирование сущностей, фейковые статусы, избыточную фрагментацию, Border-Hell и перегруженные интерфейсы).

---

## 2. Ключевые архитектурные столпы

1. **Rail Pipeline & Engineering Reward Engine**: Детерминированный 6-фазный рельсовый конвейер разработки (`Scope Lock & Sizing → Discovery & Reuse → Architecture & Naming → Surgical Execution → Defensive Verification → Reward Score & Report`) с бинарной матрицей «DO & ENCOURAGED» vs «DON'T & FORBIDDEN» и прогрессной плашкой вознаграждения качества (Score 0–100).
2. **UI, Layout & Visual Discipline**: Отсутствие рамок по умолчанию (кнопки, карточки, навигация, инпуты), Subtle Border Fallback при одинаковом фоне, запрет декоративного мусора (UI Zero-Slop), адаптивность с первого шага (Responsive by Default: 320px–1440px+), Flex Text Safety, Gap Before Margin, No Div-Hell, No Positioning as Layout, итоговый Final UI Audit.
3. **Modularity & Code Simplicity**: Организация кода по доменной ответственности (`auth/`, `payments/`, `storage/`), нативные системы модулей, принцип Main File, порог маленького модуля (30–50 строк), правило трёх (Rule of Three), тест старшего инженера и проверки простоты без разрушения архитектуры проекта, строгий запрет мусорных папок (`utils/`, `helpers/`).
4. **Architecture, Predictable Naming & Workflow**: Структура кода сама объясняет назначение системы человеку; функции называются строго по выполняемому действию (`calculatePrice`, `createUser`); запрет абстрактных названий (`doSomething`, `process`, `handle`); предсказуемость терминологии по всему проекту; сквозной 24-шаговый алгоритм разработки; запрет папок ради одного файла.
5. **Defensive Architecture & Security Verification**: Zero-Trust Input Validation (строгие схемы DTO без неизвестных полей), обязательная изоляция в слое данных (Data Layer Binding против BOLA/IDOR), параметризация запросов против SQLi, безопасный рендеринг без XSS, аудит Supply Chain (защита от Typosquatting и проверка CVE).
6. **Rule Enforcement & Execution Discipline (P0–P3)**: Процедурный механизм принудительного исполнения правил. Иерархия: P0 Scope / User Request > Existing Project Architecture > Framework Conventions > Simplicity / Modularity > Optional Abstractions.
7. **Scope Lock**: Фиксация 4 квадрантов границ перед стартом (`[REQUESTED]`, `[PROTECTED]`, `[REQUIRED]`, `[FORBIDDEN]`). Data-Flow без спекулятивной инфраструктуры.
8. **Pre-Action Gate & Audit Stamp**: Обязательный шлюз из 5 бинарных проверок и штамп перед любым мутирующим вызовом инструментов. Блокировка действий при несоответствии.
9. **Rule Trigger Map & Violation Protocol**: Автоматическая привязка правил к намерениям и строгий протокол восстановления (`STOP → IDENTIFY → REVERT → REPLAN → FIX → VERIFY → PROCEED`).
10. **Сохранение первоначального смысла**: Сначала понять главную цель и проблему, зафиксировать требования, построить архитектуру, и только затем писать код.
11. **16-блочный предпроектный анализ (P2-1)**: Запрет на слепую разработку без структурированной декомпозиции для крупных проектов (`FULL_PROJECT`).
12. **Оркестрация субагентов (4–10 ролей)**: Разделение зон ответственности для крупных проектов; запрет оверинжиниринга на точечных задачах (Task Sizing).
13. **Кроссплатформенный UI и адаптивность окон**: Принцип Window-First Adaptivity, Content Priority (PRIMARY, SECONDARY, OPTIONAL), запрет жестких координат и аудит переноса Web → Desktop.
14. **Дизайн-ограничения (Anti-AI-Slop & Zero-Emoji)**:
   - Полный запрет эмодзи в интерфейсах;
   - Запрет псевдоконтекста продукта (No Fake Product Context: версии в шапке, выдуманные статусы вроде `IDLE SCAN`, фейковые движки);
   - Radical Header Minimalism: запрет зеленых точек слева сверху, бейджей протоколов и тарифов в шапке;
   - Purity Formula: интерфейс строится по эталонной формуле максимальной чистоты;
   - Border Last: структура создается воздухом, отступами и типографикой, а не сплошными рамками.
15. **Правило трех действий**: Любой ключевой пользовательский сценарий выполняется максимум за 3 шага.
16. **Долговременная память предпочтений (Design Memory)**: Накопление User Design DNA и строгий реестр запрещенных решений (Avoid Rules) в `DESIGN_MEMORY.md`.

## 3. Дисциплина поведения агента (Правила 9–18)

* **9. Строгое соответствие запросу**: Реализовывать только то, что явно запросил пользователь; никаких элементов «для красоты» или «на будущее».
* **10. Универсальная модульность и простота кода**: Группировка по ответственности, нативные модули платформы, Main File Control Flow, запрет мусорных папок `utils/`, запрет искусственного дробления строк. Для `SURGICAL_TASK`: минимальность выше модульности (P1-3 > P1-10).
* **11. Очистка кода**: Удалять сиротский код собственных изменений, не трогать чужой легаси-код без запроса.
* **12. Минимум проверок**: Только необходимые проверки; запрет проверок «на всякий случай» и обработки гипотетических ошибок.
* **13. Принцип минимального изменения**: Хирургические правки, запрет Drive-by Refactoring и Style Drift, тест diff (каждая строка восходит к запросу).
* **14. Запрет самовольного расширения**: Категорический запрет самостоятельно придумывать UI-элементы, тексты, состояния, API и абстракции.
* **15. Сначала искать, потом создавать**: Сначала найти → переиспользовать → адаптировать. Исправлять оригинал вместо создания обходных теневых дубликатов.
* **16. Краткая и понятная коммуникация**: Меньше текста — больше полезной информации. Без «воды», пошагового спама, лишних логов и формальностей.
* **17. Инженерная простота и проверка шагов**: Конструктивное возражение при оверинжиниринге (Push back when warranted), тест старшего инженера («было 200 строк, перепиши в 50») и обязательная привязка проверки к каждому шагу (Step → Verify).
* **18. Принудительное соблюдение правил и рельсовый конвейер**: Фиксация Scope Lock, 5 бинарных проверок Pre-Action Gate, переход строго по 6 фазам конвейера и расчет Engineering Reward Score.

## 5. Подключение скилла

### Google Antigravity
Поместите директорию `go-build` в `~/.agents/skills/go-build/` или проектную папку `.agents/skills/go-build/`. В `GEMINI.md` добавьте:

```markdown
Для ВСЕХ задач разработки и программирования агент обязан активировать и строго соблюдать архитектурный стандарт из скилла go-build (~/.agents/skills/go-build/SKILL.md).
```
