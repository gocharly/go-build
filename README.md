# GO-BUILD

Чистый код без шума. Спокойный интерфейс без рамок.

AI-ассистенты часто генерируют лишнее: обвешивают интерфейс серыми линиями, создают папки ради одной функции и рефакторят то, о чем их не просили. 

**GO-BUILD** возвращает разработку к фокусу. Это правила для Claude, Antigravity, Cursor и других агентов, которые учат модель делать ровно то, что нужно — просто, надежно и со вкусом.

---

### Главные принципы

- **Смысл важнее кода.** Сначала понять проблему пользователя, затем писать решение. Не придумывать фичи «на будущее».
- **Воздух вместо рамок.** Карточки и кнопки разделяются отступами, фоном и типографикой (`Border Last`). Никакого Border-Hell.
- **Хирургическая точность.** Каждая измененная строка в diff решает конкретную задачу. Соседний код не трогается.
- **Никаких эмодзи и AI-штампов.** Никаких ракет, светящихся точек и псевдостатусов. Только интерфейс продукта.
- **Защита по умолчанию.** Все формы и API закрыты строгими схемами, каждый запрос к базе привязан к пользователю.

---

### Как работает агент

Конвейер разработки детерминирован и разбит на 6 простых шагов:

| Шаг | Что делает агент |
|---|---|
| **1. Границы (Scope Lock)** | Фиксирует, что запрошено, а что запрещено трогать. Без этого код не пишется. |
| **2. Поиск (Discovery)** | Сначала находит готовые функции и типы в проекте, чтобы не плодить дубликаты. |
| **3. Архитектура** | Называет функции строго по действию (`calculatePrice`, `createUser`), группирует по смыслу. |
| **4. Точечная сборка** | Пишет минимальный чистый код, сохраняет стиль проекта. |
| **5. Проверка** | Сам запускает тесты и линтер. Никаких «вот команды, выполните сами». |
| **6. Оценка качества** | Сверяет результат с чек-листом и показывает плашку качества (0–100). |
