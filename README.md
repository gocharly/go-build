# GO-BUILD

**Архитектурный стандарт разработки цифровых продуктов и регламент дисциплины AI-ассистентов**

Версия стандарта: **v1.12.0**

---

## 1. О стандарте

**GO-BUILD** — это строгий инженерный стандарт и скилл для автономных AI-ассистентов (Google Antigravity, Claude Code, Cursor, Roo, Windsurf), ориентированный на комплексную разработку цифровых продуктов от первоначальной идеи до протестированного, чистого решения.

Стандарт ликвидирует фундаментальные проблемы генеративного кода («AI-slop», декоративные заглушки, самовольное расширение скоупа, дублирование сущностей, фейковые статусы и перегруженные интерфейсы).

---

## 2. Ключевые архитектурные столпы

1. **Сохранение первоначального смысла**: Сначала понять главную цель и проблему, зафиксировать требования, построить архитектуру, и только затем писать код.
2. **Обязательный 16-блочный предпроектный анализ**: Запрет на слепую разработку без структурированной декомпозиции.
3. **Оркестрация субагентов (4–10 ролей)**: Разделение зон ответственности (Product Analyst, System Architect, Frontend Engineer, Backend Engineer, QA, Security, UX Reviewer, Performance, Code Reviewer).
4. **Кроссплатформенный UI и адаптивность окон**: Принцип Window-First Adaptivity, Content Priority (PRIMARY, SECONDARY, OPTIONAL), запрет жестких координат и аудит переноса Web → Desktop.
5. **Дизайн-ограничения (Anti-AI-Slop & Zero-Emoji)**:
   - Полный запрет эмодзи в интерфейсах;
   - Запрет псевдоконтекста продукта (No Fake Product Context: версии в шапке, выдуманные статусы вроде `IDLE SCAN`, фейковые движки);
   - Radical Header Minimalism: запрет зеленых точек слева сверху, бейджей протоколов и тарифов в шапке;
   - Purity Formula: интерфейс строится по эталонной формуле максимальной чистоты;
   - Border Last: структура создается воздухом, отступами и типографикой, а не сплошными рамками.
6. **Правило трех действий**: Любой ключевой пользовательский сценарий выполняется максимум за 3 шага.
7. **Долговременная память предпочтений (Design Memory)**: Накопление User Design DNA и строгий реестр запрещенных решений (Avoid Rules) в `DESIGN_MEMORY.md`.

---

## 3. Дисциплина поведения агента (Правила 9–16)

* **9. Строгое соответствие запросу**: Реализовывать только то, что явно запросил пользователь; никаких элементов «для красоты» или «на будущее».
* **10. Модульность**: Повторно используемую логику выносить в модуль с одной понятной ответственностью и публичным API через `import`.
* **11. Очистка кода**: Удалять неиспользуемый код, мёртвые функции, временные логи и импорты.
* **12. Минимум проверок**: Только необходимые проверки; запрет проверок «на всякий случай» и обработки гипотетических ошибок.
* **13. Принцип минимального изменения**: Менять только необходимые файлы и код, не рефакторить несвязанные части.
* **14. Запрет самовольного расширения**: Категорический запрет самостоятельно придумывать UI-элементы, тексты, состояния, API и абстракции.
* **15. Сначала искать, потом создавать**: Сначала найти → переиспользовать → адаптировать. Исправлять оригинал вместо создания обходных теневых дубликатов.
* **16. Краткая и понятная коммуникация**: Меньше текста — больше полезной информации. Без «воды», пошагового спама, лишних логов и формальностей.

## 4. Структура репозитория

```text
go-build/
├── SKILL.md                 # Полная спецификация стандарта и инструкции скилла
├── DESIGN_MEMORY.md         # Долговременная память дизайн-паттернов и Avoid-правил
├── CHANGELOG.md             # Хронология версий и чеклисты Study / Review
├── updates/                 # Детальные логи каждого обновления стандарта
├── templates/               # Шаблоны анализа (16 блоков) и регламент команды
├── references/              # Справочники верстки, кроссплатформенности и ресурсов
└── research/                # База исследований дизайн-систем
```

## 5. Подключение скилла

### Google Antigravity
Поместите директорию `go-build` в `~/.agents/skills/go-build/` или проектную папку `.agents/skills/go-build/`. В `GEMINI.md` добавьте:

```markdown
Для ВСЕХ задач разработки и программирования агент обязан активировать и строго соблюдать архитектурный стандарт из скилла go-build (~/.agents/skills/go-build/SKILL.md).
```
